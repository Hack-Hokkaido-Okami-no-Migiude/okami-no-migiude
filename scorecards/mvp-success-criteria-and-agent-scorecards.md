# Okami no Migiude MVP success criteria and agent scorecards

Use the build brief for product scope. Use this companion to agree on the evidence for each assignment and review the finished work. The demo case is a family-run Jozankei inn in Sapporo City (札幌市).

## MVP success criteria

Use the [owner journey scorecard](owner-journey-scorecard.md) and [staff and advisor journey scorecard](staff-journey-scorecard.md) to run the integrated walkthrough and record evidence for the checks below.

| ID  | Area                          | Pass when                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| --- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Signup and language           | A new owner can start from the homepage, switch the website between Japanese and English, and create an account using name, email, business name and municipality. The optional contact and notes fields can be left empty. The owner can sign back in with the account email and password. The language choice persists across pages and later visits.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 2   | Consent and browser interview | A signed-in owner can start when ready. The site explains the Shima Enaga interview and asks for consent to the recording and transcription handling, the automated report processing, and staff access before the conversation begins. The interview runs as a server-minted WebRTC voice conversation with the ElevenLabs agent, started only after the consent gate completes (the page mints the conversation token then); the page has no scripted sample interview and no local microphone recording. Verify that withholding consent prevents the conversation from being minted or started and that ending the call finishes the interview early. The conversation's length is managed by the agent, with no visible timer. When the agent is not configured, the page shows an honest unavailable state.                                                                                                                                                                                                       |
| 3   | Interview handoff             | The website receives the completed interview data through the agreed interface and associates it with the correct owner. For the ElevenLabs agent this is the post-call transcription webhook, matched by the mint-time conversation↔interview association the server records when the page mints the conversation token (the interview id dynamic variable remains the in-call fallback), and the association survives the owner leaving the interview page before the webhook arrives. The research lifecycle is wired to the interview conversation, not to the removed voice sessions: the stored interview transcript drives the assessment's deep research pass, and the agent's in-call research tool works for interview conversations. The former standalone voice surface is gone: the `/voice` page and its navigation entry no longer exist, and the voice-session API only mints conversations for an active interview. Record whether the live agent, webhook delivery, and live research were exercised. |
| 4   | Report processing and content | Completing the interview starts report preparation automatically. For the live agent interview the report engine is the Dify post-call assessment, which requires `DIFY_API_KEY`; without it the transcript is stored but no report is generated and the site shows an honest unavailable state. The owner can return while it runs and see the finished report later. The report maps the current workflow and, where a recommendation changes the process, diagrams the proposed workflow alongside it. It lists the practical opportunities found in the interview and shows current effort, potential time savings, estimated implementation effort and cost, and the basis for those estimates. Show existing-tool or custom options where useful. If preparation fails, the site shows an unavailable state and sends no report-ready email.                                                                                                                                                                      |
| 5   | Owner delivery and privacy    | A ready report triggers one email containing a link to the private report. The owner signs in and can open and download it. Verify that a signed-out visitor and a different owner cannot access the report or download through the link. Live delivery uses Resend, the only configured live mail service (`MAIL_RESEND_API_KEY`); without a key the labeled local `.eml` outbox substitute delivers instead.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 6   | Staff and consultation        | Designated staff are notified and can view the report as soon as it is ready. Another user without staff access cannot use the staff view. The owner can request a consultation, and designated staff can see the request.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 7   | Integrated demo and handoff   | The lead runs the merged app through the inn journey, verifies the access checks, and supplies run instructions, evidence, and a list of dependencies with live verification still pending. Label any test substitute in the demo and handoff.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Record a result against each criterion. Use **Pass**, **Verified with substitute**, **Failed**, **Blocked**, or **Unverified**. For a check with both local and external parts, record each result. A test substitute can demonstrate the app workflow. Record live provider verification separately. Report any open MVP check and its impact on the demo. ### Automated evidence map

Format and lint gates are `npx prettier --check .` and `npx eslint app server shared scripts tests --quiet`. A journey check can cite an automated result as evidence when the test covers the same behavior; record live-provider checks separately from substitute-backed automated results. The app ships labeled substitutes for the demo, including the local `.eml` mail outbox (`server/mail/local.ts`, which runs whenever the Resend API key is absent — it is a substitute, not an alternative service), the configurable voice providers (`server/voice/providers.ts`) with loopback QA stubs, the loopback Dify stub (`DIFY_API_BASE_URL`) for the assessment pipeline, and the headless demo interview API — automated verification drives `POST /api/interviews/start` with `mode: 'demo'` directly; the `/interview` page itself has no sample UI.

## Lead agent scorecard

Score the merged result after independent checks. The lead owns fixes and integration until the demo can be handed over.

| Dimension                | Evidence for 2 points                                                                                                                                                                             |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Scope and priorities     | The work plan starts with the owner journey. Each delegated task maps to acceptance criteria. Stretch work follows the core path.                                                                 |
| Delegation and ownership | Each worker received the goal, file ownership, inputs, dependencies and checks. Shared interfaces have named owners and coding assignments follow the build brief’s model and effort requirement. |
| Integration              | The lead reviewed and integrated the workers’ changes, exercised the shared interfaces, and rechecked fixes in the merged app.                                                                    |
| Acceptance               | The lead ran the inn journey, checked owner and staff access, and recorded a result and evidence for each MVP criterion.                                                                          |
| Demo and handoff         | The run instructions work. The handoff identifies the demo path, exact checks performed, test substitutes and remaining blockers or live checks.                                                  |

## Subagent scorecard

Use one scorecard per assignment. The worker supplies evidence and the lead checks it at review.

| Dimension                   | Evidence for 2 points                                                                                                                                  |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Scope and ownership         | The agreed outcome is delivered in the owned files. Changes to shared contracts or another worker’s files were coordinated.                            |
| Behaviour and integration   | The change works through its normal entry point, meets the assigned checks and respects the shared inputs and outputs.                                 |
| Maintainability and commits | Names and file structure explain the work. Changes follow the coding conventions and are grouped in small, coherent Angular-style commits.             |
| Verification                | The handoff gives reproducible commands or browser steps and their actual results. Failures, missing dependencies and test substitutes are identified. |
| Handoff                     | The lead can find the commits and changed paths, integrate the result, and see what is ready or blocked.                                               |

Examples of assignment evidence include a signup and language-switch run for the website worker, consent and timed-stop tests for the interview worker, a diagram and report-email run for the report worker, and role-access and consultation checks for the staff worker.

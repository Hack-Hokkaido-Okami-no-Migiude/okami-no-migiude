## Owner journey (Japanese first)

- **Entry:** `GET /` is Japanese-first owner self-service (`聞く → 見える化 → つなぐ`): an authorized owner can start or resume their own business interview without staff operating it. Redirect `/shima` to `/`; preserve the detailed former root reviewer at **`/workbench`**. Guard private SSR/Nuxt data before serialization; an anonymous landing shows only generic sign-in/demo choices. `/quests` is separate and mode-gated. Keep original evidence language; English optional.
- **Hear:** private browser call, solo or coworkers sharing the mic. The app asks one plain Japanese question at a time (routine, manual time, tools, exceptions); select a relevant open gap in committed analysis or a bounded prompt. Owner can switch topic, skip/repeat, finish, correct, type or stop. Target ~30 minutes (warn at 28, wrap at 30, stop by 35). Show question text if speech fails; reconnect explicitly after reauthorization. No fixture substitution, diarization or full-duplex promise.
- **One intake path:** on explicit Finish, group final STT segments, review and commit one original-language transcript row or first-class answer, **not both**. Reuse stable turn/source IDs, revisions, durable dedupe, ordered CAS and cascade. No partial/assistant text as evidence. Paste uses existing reviewed PUT; batch audio returns unpersisted draft. Run the same discovery/proposal pipeline after commit; coalesce per authorized revision/batch, discard late results, keep the last good map marked stale on failure. Without permission/config, intake may stay local and analysis is unavailable; never use fixture analysis on real input.
- **Map:** private processes, cited effort, simplifications/automation and unknowns. Weekly spent = occurrences/week × minutes/occurrence for the same step/season; basis and reported/assumed/unknown are distinct, `null` ≠ zero. Editable assumptions require a reason; future savings have a separate period, basis and residual work. No invented facts/transitions or double-counting. Give a self-serve setup/checklist with prerequisites, success check and manual fallback; package engineer work only where needed.
- **Match:** package includes proposed change, deliverables, acceptance criteria, skills, dependencies, estimated benefit, proposed yen and date. **Accept / 引き受ける** is private intent; **Reshape / 内容を調整** edits/rebases and clears decisions/approvals; **Decline / 見送る** persists, reopened only by explicit reshape/rebase. Mark stale on basis change. Show every exact preview field, with separate yen confirmation and card approval. Claim reserves one slot. Owner marks done after claim and acceptance criteria, with a durable private **完了** badge, not certification/payment. Demo booking/payment/subsidy matching are mocks. Real small-task payment is direct outside the app; the map may inform, not approve, subsidy applications.

## Consent and transport — gate at the server

1. Minimal private roster: stable server ID, neutral label and owner/coworker role; no inferred speaker identity. Each person, including solo owner, acknowledges personally via authenticated seat or short-lived one-use seat grant; no blanket owner checkbox. Record participant/actor, purpose, notice version, actual provider and server time/status. Show Japanese notice before real intake, mic prompt or provider contact: AI, data, subprocessors, purpose, region/retention/deletion limits, stop/revoke and text alternative. Paste/recording requires permission for everyone represented.
2. Separate `local-capture`, `recorded-stt`, `live-voice` (STT/TTS) and `external-analysis` (discovery/proposal). Local scope precedes intake; external scopes need valid receipts for all relevant participants **and** explicit operation confirmation (per call, upload or disclosed analysis revision/batch). Roster, notice or provider changes stop affected capture until reauthorized. Any participant can stop; each can revoke their own purpose; no implied publication consent. Safety stop/revoke cannot be blocked by stale ordinary revision.
3. Prefer same-origin server relay so the server can cut off audio. Check mode, actor, business/session, roster, active epoch and scope at connection and **each** forward/send/retry, including TTS and legacy analyze/proposal/transcribe, both analysis stages. Serialize new send admission vs stop/revoke; close/abort streams/fetches and mic tracks; discard queued/late data; explicit resume only. Already sent bytes cannot be recalled. Stop closes the epoch; revoke durably removes permission. No raw audio stored by default; linked deletion purges artifacts/approvals/quests/claims and cannot replay them. Report local deletion separately from provider/backup cleanup.
4. Use ElevenLabs Scribe v3 Live Japanese STT + TTS for the selected question only; pause mic forwarding during playback. Server keys, fixed hosts, byte/time/rate/cost caps; fail closed on missing config. Retain OpenAI-compatible analysis, verify through local stubs. Defer ElevenAgents, Dify, Linkup, Neo4j and Neon; consider OrcaRouter only with verified compatibility and upstream disclosure. No provider ran in this audit.

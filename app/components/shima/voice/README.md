# Shima voice client (not mounted)

Only mount `ShimaVoiceInterview.vue` in an authenticated private owner/participant view after protected relay and turn routes have been verified. Never use it to implement the public/fixture role-play. Parent supplies `available` from server-verified deployment/readiness, `consentComplete` from current individual receipts, the full Japanese provider/retention/stop notice, `/api/clients/:clientId/sessions/:sessionId/shima/interview`, and current `baseRev`. On roster/receipt or provider changes, revoke availability immediately or remount with a new key; don't rely on these props as a server security boundary. Keep a text alternative visible outside the component. The checkbox acknowledges this call only; it does not create consent receipts.

`commitTurn(turnsPath, { baseRev, turn: { turnId, questionId, text } })` must POST only the reviewed answer to the supplied scoped route. Resolve after a validated success and merge the returned revision/state; reject on failure. Handle UUID idempotency and stale CAS in the parent and never duplicate evidence after an ambiguous response. The browser allows a retry only with the same approved answer and `turnId`. `@revision` reports validated start/stop revisions for this scope. Supply `csrfHeaders` if the deployment requires a CSRF header in addition to exact Host/Origin; the native upgrade has only cookies and browser Origin, not custom request headers.

Before integration, align the server and contract on these provisional details:

- The client uses `?epoch=…` on the same-origin WebSocket. Emit `ready` before the first `question`. The browser forwards mono 16 kHz signed PCM16-LE only with a visible question and no playback. The relay must independently verify each send and `playback` control against the active epoch. The server owns all questions; any optional `audioPath` must be protected, same-origin, non-redirecting, and return bounded `audio/*` with no cache. Playback may be blocked by browser autoplay policy; the question remains available as text. A restrictive CSP needs to allow the resulting same-origin `blob:` media URL as well as the protected connect endpoints.
- A `finish` drains/finalizes one answer, immediately stops local capture and expects a scoped `draft`, not automatic evidence or another question. Keep the authorized browser stream open for review, detaching the upstream STT when needed; a `stopped`/disconnect invalidates local review. Reconcile the upstream idle limit with the browser permission prompt and TTS pauses; don't bypass stop/revoke/lifetime bounds. Repeat/skip and timed interview prompts are not included in this component.
- The provisional flat turn has `{turnId,questionId,text}`; the earlier `SHIMA-CONTRACT.md` uses a nested `input` union. Settle the route schema before mounting. A stop must close its named epoch even if `baseRev` is stale; enforce server expiry/disconnect cleanup in case the browser never receives the start response or its best-effort keepalive stop is lost. Server-initiated `stopped` has no revision in this wire, so resume may need the parent to refresh state first.

The dependency-free capture adapter uses the browser's 16 kHz AudioContext and mono ScriptProcessor for this isolated pilot seam. It fails closed on unsupported capture rather than transmitting a guessed sample rate. Its tests use in-process stubs; production browser compatibility, real microphones, speech decisions, and provider processing have not been verified.

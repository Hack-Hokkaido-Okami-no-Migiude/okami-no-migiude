## Shared TS and server seams

Single source of truth in `shared/p0/{schemas.ts,types.ts,api.ts}`: strict request and persisted Zod schemas; derive TS from schemas. `Id = string`; mutable records carry server-owned identifiers. Nullable fields use `null`, not guessed values; optional keys are only for requests/patches. Core shapes (fields with domain structure spelled out below):

- `Client { id, name }`, `SessionSummary { id, clientId, title, rev, origin: 'user'|'hotel-demo' }`, `Session = SessionSummary & { transcript: Transcript|null; workflow: Graph; questions: Question[]; opportunities: Opportunity[]; proposals: Proposal[]; discovery: Run|null; reviewNotices: ReviewNotice[] }`. Start at `rev:1`, empty collections; `Run { mode:'fixture'|'live'; completedAt:string; stale:boolean }`; `ReviewNotice { code:'ambiguous_match'|'lost_evidence'|'correction_conflict'|'answer_conflict'; targetId:Id|null; message:string }`.
- `Transcript { source:'paste'|'audio'; segments: Segment[] }` (`audio` reserved P1); `Segment { id, sourceRev, speaker:string|null, text, startMs:number|null, endMs:number|null }`, ordered in the input array; timestamps are nonnegative and ordered when supplied. Segment creation accepts no ID; edits/reorders send the existing ID and all editable fields. Preserve original English/Japanese, casing and line breaks. Paste UI splits lines, parses clearly marked speaker/time metadata without translating, and edits persisted rows by ID. Do not reuse a removed ID, or match new rows by array index. Increment `sourceRev` only when the source row changes, not on reorder.
- `EvidenceRef { sourceId, sourceRev, quote }` points to an active `Segment` or consultant `Answer { id, sourceRev, text }` in that session. Quote is a nonblank verbatim substring of stored original text; reject nonexistent/cross-session/outdated refs and copied/fabricated quotes. Render text as text, not HTML. Citation validation establishes provenance, not entailment: require the cited wording to support the actual claim; flag uncertainty rather than extrapolate.
- `Claim<T> { value:T|null; state:'client-confirmed'|'inferred'|'unknown'|'consultant-verified'; evidence:EvidenceRef[]; author:'analysis'|'consultant' }`. Unknown = `null`; inferred needs evidence and an inference label; client-confirmed needs explicit participant wording. Only a consultant action verifies submitted fields. Unsupported locked values persist as review-only, not as evidence-backed data.
- `Graph { steps: Step[]; edges: Edge[] }`. `Step { id, label:Claim<string>, role:Claim<string>, tool:Claim<string>, inputs:Claim<string[]>, outputs:Claim<string[]>, execution:Claim<'manual'|'automated'|'mixed'>, bottleneck:Claim<string>, exception:Claim<string>, graphEligible:boolean }`. `Edge { id, fromStepId, toStepId, kind:'sequence'|'decision'|'exception', condition:Claim<string>, evidence:EvidenceRef[] }`. Draw eligible steps with supported labels and evidenced edges between them. Directly support the transition, not just its endpoints; don't infer sequence from adjacency/order/layout. Decision/exception edges require evidenced conditions; unconditional sequence may use `unknown`. No placeholder nodes or edges; review-only steps are visible in details.
- `Question { id, targetStepId:Id|null, factKey, prompt, whyItMatters, priority:'high'|'medium'|'low', status:'open'|'answered'|'retired', answer:Answer|null }`. `factKey` is a canonical missing-fact key scoped to the reconciled target (`trigger`, `actor`, `tool`, `handoff`, `branch-rule`, `exception`, `frequency`, `minutes`, `integration`, `risk`); general questions use a null target. Ask only actionable unknowns that could change a result; sort by priority and stable ID. If distinct questions need the same topic/target, refine the key explicitly in shared schema before adding variants.
- `Opportunity { id, title, strategy:'simplify'|'rules'|'integration'|'ai', stepIds:Id[], evidence:EvidenceRef[], rationale, factors:{impact,frequency,effort,feasibility,risk}, benefits:string[], prerequisites:string[], risks:string[], unknowns:string[], assumptions:{monthlyOccurrences:Assumption,minutesSaved:Assumption}, hoursSavedPerMonth:number|null }`. Factors are cited `Claim<'low'|'medium'|'high'>`; rank known-factor mean (low/medium/high = 1/2/3; invert effort/risk), tie-break by more known factors then ID; all unknown last. Prefer non-AI where sufficient. `Assumption { value:number|null, basis:string, evidence:EvidenceRef[], edited:boolean }`: nonnegative finite estimates with labeled basis; server computes occurrences × minutes ÷ 60 (`null` if either input missing; zero is valid).
- `Proposal { opportunityId, graph:ProposedGraph, plan:Plan, mode:'fixture'|'live', stale:boolean }`. Proposed steps `{id,label,currentStepIds,evidence}`, edges `{id,fromStepId,toStepId,label,evidence}` use separate `pstep`/`pedge` IDs. Label hypotheses: evidence motivates changes, not proof of current work. `Plan { id, status:'draft'|'in-review'|'approved', sections:Record<PlanSection,string>, editedSections:PlanSection[] }`; sections `scope`, `businessRules`, `integrationsAuth`, `exceptions`, `humanOversight`, `milestones`, `acceptanceTests`. Approval is review only; no deployment.

Stable seams installed by slice, extended in place:

## HTTP API (JSON unless noted)

`C = /api/clients/:clientId`, `S = C/sessions/:sessionId`. All session writes require `baseRev:number`; return the complete committed `Session` unless stated. `POST` creates return `201` except analysis, proposal and demo actions (`200`). Route paths below are literal suffixes; nested Nitro files under `server/api/`. Marked **slice** routes are the first gate.

| Method/path | Request → response |
|---|---|
| `GET /api/clients`; `POST /api/clients` | list → `Client[]`; `{name}` → `Client` |
| `GET C/sessions`; `POST C/sessions` | list → `SessionSummary[]`; `{title}` → `Session` |
| `GET S` **slice** | → `Session` |
| `PUT S/transcript`; `DELETE S/transcript` | `{baseRev,segments:SegmentInput[]}` (editable fields above + optional existing `id`; paste only); DELETE `?baseRev=` with no body → cleared session (cascade graph/findings/questions/answers/opportunities/proposals/plan/fingerprints) |
| `POST /api/demo/hotel` **slice** | `{}` → `Session` (idempotent) |
| `POST S/analyze` **slice** | `{baseRev,mode,allowExternal?:true}` (`mode` = `fixture` or `live`) → `{outcome,session:Session}` (`outcome` = `updated` or `unchanged`) |
| `PATCH S/steps/:stepId` | `{baseRev,fields:Partial<EditableStepFields>,verify:boolean}`; fields are Step claims excluding ID/review flags, with `{value,evidence}` only; `verify:true` verifies submitted fields, otherwise submit as unverified correction. Must send ≥1 field. No graph topology edits. |
| `PUT S/questions/:questionId/answer` | `{baseRev,text}`; record or edit answer on that question (same answer ID, changed text increments `sourceRev`); no automatic LLM call |
| `PATCH S/opportunities/:opportunityId` | `{baseRev,assumptions}`; ≥1 of `monthlyOccurrences` or `minutesSaved` (`Assumption` without `edited`); set edit flag and recompute savings |
| `POST S/opportunities/:opportunityId/proposal` **slice** | Same request and response as `/analyze` |
| `PATCH S/opportunities/:opportunityId/plan` | `{baseRev,sections?:Partial<Record<PlanSection,string>>,status?:Plan['status']}`; ≥1 supplied key; track edited sections, reset to draft on changed text without explicit status; cannot approve stale plan |
| `GET S/opportunities/:opportunityId/plan.md` **slice** | current plan → Markdown attachment (`text/markdown; charset=utf-8`, fixed filename `implementation-plan.md`); status, opportunity, labeled savings, seven named sections; no raw transcript, generation or mutation |

Error body `{error:{code,message,currentRev?}}` (not a raw H3/provider payload): `400 invalid_input` schema, size or reference errors; `404 not_found` unknown or non-child ID; `409 stale_revision` with `currentRev` when present (reload/review before reapplying), `409 stale_artifact` for stale approval/export; `422 consent_required` or `fixture_unsupported`; `502 provider_failed`/`invalid_model_output`; `503 provider_unconfigured`/`storage_unavailable`. With no transcript, analyze returns `400`; proposal requires current discovery and a persisted opportunity. Never return transcript snippets, provider bodies or secrets in errors/logs. No client authorization beyond scope/ownership checks; bind demo locally.

## Persistence, reconciliation, provider

- **Single Node process and local durable JSON** at `NUXT_DATA_DIR` (default ignored `.data/`, outside `public/`). One versioned snapshot for atomic cross-record operations. Serialize read/modify/write commits; validate, write a same-directory unique temp file, flush, then atomically rename over the primary; clean up failed temp files, never replace a malformed primary with an empty store. No in-memory fallback, no multi-process/shared-directory support. Prefer this over native `better-sqlite3` for P0; remove the experimental dependency/external only in the approved integration diff. Configure Nitro `node-server`, not static generation/edge.
- IDs are server-assigned `cli_`, `ses_`, `seg_`, `step_`, `edge_`, `q_`, `ans_`, `opp_`, `pstep_`, `pedge_`, `plan_` + UUID; seed IDs are fixed reserved fixture constants. Model may refer to source IDs and known prior records as hints; use per-response local candidate keys for new nodes and resolve server-side. Reject collisions, duplicate local keys, dangling/self-inconsistent references and material claims with invalid evidence before CAS.
- Match validated prior ID or unique supported action/source (not label only or a broad multi-action segment); edges by reconciled endpoints/kind/branch; opportunities by affected steps/strategy/goal; questions by reconciled target + fact key. Ambiguity creates a review notice, not a duplicate or overwrite. Preserve compatible consultant edits, never overwrite verified fields, and keep unsupported locked rows review-only. Drop unmatched unverified analysis; retain answer history, manual assumptions and edited plan sections. On source changes strip invalid citations/orphan edges and stale dependent artifacts. A step correction or answer stales discovery; assumption edits stale only that proposal. After refreshed discovery stale only affected proposals; retain an orphaned draft but block approval/export. Regenerate with the same plan ID and edited sections; reset approval on upstream semantic changes.
- An answer is first-class evidence, not a synthetic transcript row. Persist immediately and hide answered question from the open list; on reanalysis supply saved answers and suppress same fact/target even if paraphrased. Keep answered/retired history. A conflicting answer or changed upstream source gets an explicit review/new fact, not an automatic reopen of the answered key. A resolved answer may ground a real sequence that was previously missing; no edge until supported.
- Check `baseRev` before work; use single-flight per session/op/revision/run key to collapse identical in-flight requests. Do not hold the store write lock across provider calls. Key canonical content (ordered source rows/revisions, answers, relevant overrides; for proposals also current graph/opportunity including assumptions; include mode, non-secret model/config identity and schema/prompt version). Exclude timestamps/aggregate `rev`/generated outputs from the relevant key. A valid existing artifact with the same key returns `unchanged` with no provider call or write; equal edits are also no-ops. CAS the whole replacement against the original rev after all stages validate; on concurrent edit/delete, discard result and return stale (never auto-retry the write). Failed runs leave good prior artifacts intact and do not cache success.
- Private `NUXT_LLM_BASE_URL`, `NUXT_LLM_API_KEY`, `NUXT_LLM_MODEL`; configurable OpenAI-compatible `POST <base>/chat/completions`, only from the server. Require per-request `allowExternal:true` in live mode after visible disclosure (operation/current transcript/answers sent to configured provider); no HTTP request if denied. Serialize transcript/answers as untrusted data separate from fixed instructions, no tool calling, strict parse/validate, bound input/output and per-call time. At most one retry per operation and only for timeout/429/5xx; no retry for bad JSON/grounding or auth errors. No live provider calls in routine tests; simulate with local HTTP stub, missing config and failing/malformed cases; real samples only with credentials and consent. P1 recording/audio consent, upload and live streaming are deferred.
